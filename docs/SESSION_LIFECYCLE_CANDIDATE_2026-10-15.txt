Drawing and resource lifetimes
1. Loaded runtime/native modules and settings resources stay ready between calls.
2. Enter binds the current work mesh, exact base-object instance and target.
3. Ordinary geometry Undo/Redo invalidates hover/candidate/depth caches and
   continues the same valid drawing session. Max owns geometry Undo records.
4. Selecting an upper modifier ends MQD. Subsequent modifier deletion and
   Undo/Redo operate as normal Max history and do not reopen MQD.
5. Passive cleanup preserves the newly chosen object/stack entry/command.
   Explicit exit restores paired launch UI only while MQD still owns it.
6. Exit releases drawing references, callbacks, hooks and previews. It does
   not unload native modules or keep an old model bound as a warm cache.
7. Settings are closed by default and opened explicitly. Once opened, the
   same window/position survives drawing start/stop; its button or X closes it.

Host adapter changes
- Struct forward declarations make early abort delegates resolve reliably.
- Optional log/stat failures no longer abort required cleanup; stop returns
  the actual cleanup result.
- Existing native bridge uses SDK CommandModeChangedCallback plus a one-shot
  deferred main-thread validation. No new modifier, service or Undo engine.
- Session tokens and command ownership protect against stale callbacks and
  delayed PBEndTrack applying to a new session/command.
- Repeated select/current-stack assignment is skipped when already correct.
- R1/R3 registration/teardown shares the final Core redraw instead of forcing
  multiple full redraws per lifecycle transition.

Native comparison and failed exploratory assertions
- Native PolyDraw's first Rotate command ends drawing and returns to Move;
  a second enters Rotate. MQD preserves this native behavior, and its later
  cleanup does not override the second command.
- Script-deleting an upper modifier without first selecting it is a different
  path from the user workflow. It is not a requirement to keep MQD active.
- Early assertions made before deferred events settled, and those two wrong
  behavior assumptions, are retained in private run receipts. The final
  matrix waits between phases and tests the confirmed user workflow.
